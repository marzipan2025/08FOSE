# unslop 감사 001 · 2026-11-09

- 대상: 08FOSE v 0.8.26 + 작업 중인 라이트 2번 악센트(#607CEF / #303C4C), `Sources/FontGrid` 코드와 테스트 빌드 화면
- 기준: heydamir/unslop `skills/unslop/SKILL.md`, `references/signs.md`, `references/tokens.md` (CC BY 4.0, Damir Sokolovsky @heydamir)
- 이 규칙은 React·HTML 웹 화면 기준이라 히어로, 랜딩, 차트, 통계 카드 항목은 해당 없음.
- 아무것도 고치지 않았다. unslop 절차도 감사 후 방향을 보여 주고 답을 기다린 뒤에 고치게 되어 있다.

## 판정: 가벼운 슬롭 (Polish mode)

unslop은 결과를 셋으로 나눈다. 08FOSE는 가운데인 **"대부분 디자인되어 있고 신호가 몇 개 남은 화면"**이다.
보라 그라데이션, 글로우, 이모지, 느낌표, 과장 문구, 반짝이 배지, 반복 애니메이션은 하나도 없다.
그래서 규칙대로라면 **찾은 것만 고치고** 팔레트, 서체, 레이아웃은 유지한다. 큰 아이디어는 제안으로만 남긴다.

## 방향 (unslop이 요구하는 다섯 줄)

- **제품:** 내 맥에 깔린 폰트를 같은 문장으로 한눈에 비교하고, 고르고, 메모해 두는 디자이너용 도구
- **성격:** 조용하다, 정확하다, 수집가 같다
- **세계:** 활판 인쇄소의 견본첩과 서랍장. 종이, 잉크, 활자 케이스
- **빛나는 순간:** 격자에 크게 찍힌 샘플 문장 자체. 셀 하나하나가 다른 서체의 표본이다.
- **시그니처:** 가나다·A–Z 인덱스 줄. 다른 앱에는 없는, 이 앱만의 길잡이다.

이 앱은 unslop이 말하는 "크롬은 조용히, 풍부함은 콘텐츠에"를 이미 하고 있다. 색과 개성은 폰트 샘플이 맡고, 버튼과 패널은 무채색이다.

## 발견 사항

| # | 우선 | 분류 | 내용 | 바꾸면 |
|---|---|---|---|---|
| 1 | 높음 | 색 · 표면 | 라이트 월페이퍼가 창 전체에 곱해져서 **패널과 셀 바탕까지 분홍(2번)·노랑(1번)·초록(4번)으로 물든다.** unslop은 앱의 바탕·표면·테두리·글자는 무채색이어야 하고, 바탕이 한 색으로 읽히면 지나친 것이라고 본다. 색은 악센트와 콘텐츠가 맡아야 한다는 입장. | 월페이퍼를 패널 바깥(가운데 격자 뒤 여백)에만 깔거나, 셀과 사이드 패널 위에서는 불투명도를 더 낮춘다. 월페이퍼가 앱의 성격 중 하나라면 지금처럼 두고 "의도한 예외"로 적어 둔다. |
| 2 | 중간 | 서체 | 섹션 제목 FILTERS · VIEW · PINNED · TAGS · GLYPHS가 대문자 + 자간 0.6 + 굵게(bold). 상세 화면 정보 라벨도 `.textCase(.uppercase)`. unslop이 대표적인 신호로 꼽는 "대문자 + 넓은 자간 라벨"이다. | 문장형(`Filters`, `Pinned`)에 자간 0, 무게 medium(500). anti-slop 감사(7번)에서는 macOS 사이드바 관례라 유지를 권했으니, 두 규칙이 엇갈리는 항목이다. |
| 3 | 중간 | 서체 | 굵게(700)가 20곳: 팝업 제목(15pt), 설정 제목, 상세 화면 폰트 이름(23pt), 섹션 제목 등. unslop은 400·500, 드물게 600까지만 쓰고 위계는 크기와 색으로 만들라고 한다. | 제목류를 `.semibold`(600) 또는 `.medium`으로 낮추고 크기로 위계를 잡는다. 토스트는 이미 semibold. |
| 4 | 중간 | 숫자 | 셀 오른쪽 위 굵기 개수가 `01`, `04`처럼 앞에 0이 붙는다(`FontCell.swift:196`, `%02d`). unslop은 `07` 같은 표기를 "섞인 숫자 형식"의 신호로 든다. 같은 화면의 PINNED 54, 태그 개수는 0 없이 표기. | `1`, `4`로 바꾸고 `monospacedDigit()`으로 폭을 맞춘다. 0을 채운 것이 활자 견본 번호 같은 의도라면 유지하고 이유를 적는다. |
| 5 | 낮음 | 서체 | 상세 화면의 문자 체계·OpenType 기능 태그가 이탤릭(`FontDetailView.swift:499, 516`). unslop은 강조용 이탤릭을 금한다. 다만 여기 이탤릭은 강조가 아니라 "태그" 표시라 경계선에 있다. | 이탤릭 대신 모노 서체나 작은 키캡 모양으로 바꾼다. 그대로 두어도 큰 문제는 아니다. |
| 6 | 낮음 | 모션 | 토스트가 `.spring(response: 0.35, dampingFraction: 0.8)`로 들어온다. 감쇠가 커서 튕김은 거의 없지만, unslop은 단순 UI에 스프링 대신 ease-out 하나를 권한다. 애니메이션 곡선도 easeOut / easeInOut / easeIn 셋, 길이도 0.08~0.28초 9가지가 섞여 있다. | 곡선 하나(ease-out 계열)와 길이 세 단계(피드백 0.15, 메뉴 0.2, 등장 0.3 안팎)로 묶는다. |
| 7 | 낮음 | 간격 | 패딩 값 중 4의 배수가 아닌 것: 3, 5, 7, 9, 11, 14, 18, 26 (모두 합쳐 40곳 안팎). 대부분 버튼 안쪽 세로 5·7처럼 작은 컨트롤 안의 미세 조정이라 unslop도 허용하는 범위지만, 14·18·26은 그룹 간격이라 규칙에서 벗어난다. | 14→12 또는 16, 18→16 또는 20, 26→24로 정리. 화면에서 하나씩 확인하며. |
| 8 | 낮음 | 모서리 | 버튼 반경이 6(필터·설정)과 7(상세 액션 버튼)로 갈린다. unslop 체크리스트의 "버튼은 같은 컨트롤 반경". 값 자체(작은 버튼 4~6)는 기준 안이다. | 7을 6으로 통일. 오늘 시험했다 되돌린 "반경 절반(3)"은 unslop 기준 최소값 4보다 작아서, 되돌린 것이 규칙상으로도 맞다. |

## 통과한 것

- **색:** 보라·파랑 그라데이션, 그라데이션 글자, 색 있는 글로우·그림자 없음. 그라데이션 2곳(상세 화면 머리의 검정 농도 변화, 하단 입력바의 블러 페이드)은 한 무채색 안의 농도 변화라 허용 범위.
- **악센트:** 하나만, 선택·고정·호버에만 쓴다(anti-slop 6번 수정 후). 글자용 악센트는 바탕보다 진한 색을 따로 둔다. unslop의 "악센트를 글자로 쓰면 더 진한 색" 규칙과 정확히 같다. 라이트 2번 시험 중인 #303C4C(11.2:1)도 통과.
- **아이콘:** SF Symbols 한 세트, 장식 아이콘 없음. 이모지 0개.
- **문구:** 느낌표 0개, 과장 단어 없음. 검색칸은 `Search` 한 단어. 인사말 제목 없음.
- **그림자:** 13곳 모두 무채색 검정. 떠 있는 층(팝업, 드롭다운, 토스트)에만 있다.
- **모션:** 반복 애니메이션 없음. `scaleEffect`는 슬라이더 크기 맞춤용 1곳뿐이고, 호버 때 커지는 효과 없음.
- **템플릿 검사:** 제품 이름을 다른 앱으로 바꿔도 화면이 맞을까? 맞지 않는다. 같은 문장이 수백 개 서체로 찍힌 격자와 가나다 인덱스는 이 앱에서만 성립한다.

## anti-slop 감사(001)와 비교

| 항목 | anti-slop | unslop |
|---|---|---|
| 대문자 섹션 제목 | 관례라 유지, 이유만 기록 | 문장형으로 바꾸라 |
| 악센트 글자 대비 | 4.5:1 필요 (라이트 1·4는 소유자 결정으로 약 4:1) | 같은 기준 |
| 월페이퍼 색 물듦 | 지적 없음 | 가장 큰 항목 (1번) |
| 굵게 700, 숫자 0 채움, 스프링 | 지적 없음 | 지적 |
| 키보드 접근성, 시스템 동작 줄이기 | 지적 (4·5번) | 다루지 않음 |

## 제안만 (unslop 규칙상 바꾸지 않음)

- 시그니처인 인덱스 줄을 다른 곳에서 한 번 더 쓸 수 있다. 예: 빈 검색 결과 화면에서 가까운 글자로 이동하는 안내.

## 확인 못 한 것

- 다크 테마 화면은 이번에 다시 열지 않았다.
- 9가지 길이로 섞인 애니메이션을 실제로 비교해 보지는 않았다. 코드에서 센 값이다.
